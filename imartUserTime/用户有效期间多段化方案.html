用户有效期间多段化方案

新版 IM-共通マスタ 中 setUser 无法再修改有效期间。本文说明为什么， 以及如何用期间分割 + 无效化，在页面上支持任意组数的有效期间。

对象 jp.co.intra_mart.foundation.master.user 版本 im_master 8.0.0 范围 Java API 侧
§1

需求

页面上要能给一个用户设置多组有效期间，组数不固定，由使用者自己增删行。点击保存后写入 IM-共通マスタ。典型输入：

  • 2026/05/01 – 2028/06/01
  • 2029/06/01 – 2030/06/01

两段之间存在 2028/06/02 – 2029/05/31 这段空档，用户在这期间应当是无效状态。 难点在于：共通マスタ的期间轴不接受"空档"这种表达，必须换一种方式落库。

§2

旧写法为什么失效

以前的做法是把整个 User 对象填好、带上新的 startDate / endDate， 一次 setUser 就完成有效期间的更新。新版本这条路被封死了，javadoc 上写得很直接：

UserWriter#setUser

ユーザを登録します。すでに登録されている場合は更新されます。このメソッドで期間は変更できません。

原因是 userCd / termCd / startDate / endDate 这四项现在是定位记录用的 key，必须和库里已有的期间完全一致。 setUser 只负责改"某个期间内部的内容"，改不了期间本身的边界。

期间边界的操作被拆到了专用方法上：

方法作用注意
separateTermUser(bizKey, termCd, date) 在指定日把一个期间切成两段 分割日之前的段继承原 termCd，之后的段拿到新 termCd
mergeBackwardTermUser(bizKey, termCd) 与前一个期间合并 前一个期间的数据会丢失
mergeForwardTermUser(bizKey, termCd) 与后一个期间合并 后一个期间的数据会丢失
moveTermUser(bizKey, term) 改期间的开始日 / 结束日 扩过相邻期间时，被覆盖的期间会被删除
setUser(user) 写入某个期间内部的内容 + 有效/无效标志 不能改期间边界
§3

核心模型：用无效段填满空档

IM-共通マスタ 的期间轴从 システム開始日（1900/01/01）到 システム終了日（2999/12/31） 连续铺满，中间不允许留空。所以"有效期间是断开的"不能靠留白表达， 而是：把轴切成多段，再把不该生效的段标记为无效。 管理者操作指南对无效化的定义是「無効化すると、その期間は存在しないものとして扱われます」。

页面输入 — 只有有效期间，组数不定

2026/05/01
– 2028/06/01 有効
2029/06/01
– 2030/06/01 有効

buildTimeline() — 用无效段补满空档

落库的期间轴 — 5 条记录，连续无空洞

1900/01/01
– 2026/04/30 無効
2026/05/01
– 2028/06/01 有効
2028/06/02
– 2029/05/31 無効
2029/06/01
– 2030/06/01 有効
2030/06/02
– 2999/12/31 無効

※ 宽度为示意，非按实际时长比例。

无效标志落在 User#setDisable(boolean) 上（javadoc 写作「削除フラグ」， 由 ITerm / IDisable 继承而来）。相应地， 所有读取都必须带 isDisable = true， 否则已经设为无效的段在下次编辑时根本查不出来。

§4

实现：三步流水线

页面提交上来的是一个长度不定的有效期间 list。服务端一次保存分三步走， 三步是严格有序的 —— 必须先把期间轴的形状调对，才能往每一段里写内容。

1

推导完整期间轴 buildTimeline()

排序 → 合并相邻/重叠的输入 → 用无效段把空档和首尾补满。

// 相邻或重叠的有效期间先并成一段，避免产生无意义的切点
for (ValidPeriod p : periods) {
    if (merged.isEmpty()) { merged.add(p); continue; }
    ValidPeriod prev = merged.get(merged.size() - 1);
    if (!p.getFrom().after(addDays(prev.getTo(), 1))) {
        Date newTo = prev.getTo().after(p.getTo()) ? prev.getTo() : p.getTo();
        merged.set(merged.size() - 1, new ValidPeriod(prev.getFrom(), newTo));
    } else {
        merged.add(p);
    }
}

// 用无效段填满，覆盖 sysStart ~ sysEnd 全区间
Date cursor = sysStart;                          // AppCommonManager#getSystemStartDate()
for (ValidPeriod p : merged) {
    if (p.getFrom().after(cursor)) {
        timeline.add(new TermSegment(cursor, addDays(p.getFrom(), -1), false));
    }
    timeline.add(new TermSegment(p.getFrom(), p.getTo(), true));
    cursor = addDays(p.getTo(), 1);
}
if (!cursor.after(sysEnd)) {
    timeline.add(new TermSegment(cursor, sysEnd, false));
}

边界情况一并覆盖：有效期间恰好从 1900/01/01 开始时不生成头部无效段， 恰好到 2999/12/31 结束时不生成尾部无效段，一条都没填时整条轴是一段全无效。

2

对齐期间边界 reconcileTerms()

分割 —— 遍历第二段起的每个开始日，如果它还不是切点就切开：

for (int i = 1; i < timeline.size(); i++) {
    Date boundary = timeline.get(i).getStart();

    // 每次分割后 termCd 会重排，所以循环体内重新取，不能提到外面
    ITerm[] terms = sortByStart(manager.getUserTermList(bizKey, true));
    ITerm target  = findContaining(terms, boundary);
    if (isSameDay(target.getStartDate(), boundary)) continue;

    manager.separateTermUser(bizKey, target.getTermCd(), boundary);
}

结合 —— 上一次保存可能留下多余切点（这次改成了更少的组数），逐个并掉：

Set<Long> wanted = /* timeline 中第 2 段起的所有开始日 */;

while (true) {
    ITerm[] terms = sortByStart(manager.getUserTermList(bizKey, true));
    String mergeTargetCd = null;
    for (int i = 1; i < terms.length; i++) {   // 首段开始日动不了
        if (!wanted.contains(truncate(terms[i].getStartDate()).getTime())) {
            mergeTargetCd = terms[i].getTermCd();
            break;
        }
    }
    if (mergeTargetCd == null) break;
    manager.mergeBackwardTermUser(bizKey, mergeTargetCd);  // 每并一次结构就变，重来
}

合并会丢数据，但第 3 步会把每一段整体覆写，所以这里不用担心。实际代码里给这个 while 加了循环上限做保护。

3

写入有效/无效 applyDisableFlags()

此时库里的期间数量和边界已经和 timeline 一一对应，逐段覆写即可。

ITerm[] terms = sortByStart(manager.getUserTermList(bizKey, true));

for (int i = 0; i < terms.length; i++) {
    ITerm term      = terms[i];
    TermSegment seg = timeline.get(i);

    // isDisable=true，否则取不到已无效化的期间
    User user = manager.getUser(bizKey, term.getStartDate(), true);

    // setUser 的 key 四项必须和取出来的完全一致
    user.setUserCd(bizKey.getUserCd());
    user.setTermCd(term.getTermCd());
    user.setStartDate(term.getStartDate());
    user.setEndDate(term.getEndDate());

    user.setDisable(!seg.isEnabled());   // 无效 = 该期间视为不存在

    manager.setUser(user);
}

回读（画面初期表示用）

for (ITerm term : sortByStart(manager.getUserTermList(bizKey, true))) {
    User user = manager.getUser(bizKey, term.getStartDate(), true);
    if (user != null && !user.isDisable()) {
        result.add(new ValidPeriod(term.getStartDate(), term.getEndDate()));
    }
}

无效段被过滤掉，页面上又变回"只有几组有效期间"的样子，和保存时的输入形状对称。

§5

实现时的坑

termCd 会重排

每次 separateTermUser 之后必须重新 getUserTermList。把期间列表缓存在循环外面，第二次分割就会拿着失效的 termCd 去操作。

isDisable = true

所有 getUserTermList / getUser 都要传 true。漏掉的话，上次设为无效的段查不出来，分割时会找不到目标期间而报错。

事务

共通マスタ更新系 API 必须在事务内执行。分割成功、setUser 失败的话，期间轴会停在半成品状态，下次打开页面就是乱的。

merge 会丢数据

mergeBackward / mergeForward 会丢掉一侧期间的数据。只用来消除多余切点，不要拿它当"缩短期间"用 —— 那是 moveTermUser 的活。

重叠输入

buildTimeline 会静默地把重叠区间合并掉，用户看不出自己填错了。重叠校验放在前端，提交前弹出提示。

多语言

若用了 setPutLocaleElement 存多语言，第 3 步要按 locale 逐个 getUser(bizKey, date, locale, true) 再各自 setUser，否则会丢掉其它语言的记录。

账号有效期间

这套只改共通マスタ侧。若需求是"无效期间内不能登录"，账号侧的 有効期間（imm_account，单一区间）还得另外联动，那不归 UserManager 管。
